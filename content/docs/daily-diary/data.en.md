## The storage keys

Everything lives in `localStorage`. Five keys, each with its version in the name:

| Key | What it stores |
| --- | --- |
| `diario.entries.v1` | The saved entries: the notebook |
| `diario.drafts.v1` | Text drafts while you write |
| `diario.pendiente-dia.v1` | Changes for a day that is not in the notebook yet |
| `diario.setup.v1` | Your customisable lists: `counters` and `parts` |
| `diario.thoughts.v1` | The sea's bottles |

## An entry

Each entry is stored as JSON in `diario.entries.v1`:

```json
{
  "id": "…",
  "date": "2026-09-30",
  "dayNumber": 27,
  "mood": 4,
  "sleepHours": 7.5,
  "studyHours": 2,
  "energy": 3,
  "stress": 2,
  "bestOfDay": "…",
  "differentToday": "…",
  "generalDay": "…",
  "tomorrow": "…",
  "wordOfDay": "…",
  "capsule": "…",
  "gratitude": ["…", "…", "…"],
  "goals": ["…"],
  "tags": ["…"],
  "counters": { "water": 6, "ejercicio": 30, "p-31": 2 },
  "parts": { "p-12": "what you wrote in your own part of the day" },
  "habits": { "h-3": true, "h-7": false },
  "createdAt": "…",
  "updatedAt": "…"
}
```

The **day number** is computed automatically from the first entry's date.

> [!IMPORTANT]
> Whatever is not in that list is **not saved**: `validateEntry` cleans and rejects anything it does not recognise. It is a deliberate defence against corrupt or unexpected data.

## Drafts

Half-written texts live separately, in `diario.drafts.v1`:

```json
{ "entrada:2026-10-04": { "data": { "generalDay": "what I was writing…" }, "savedAt": "…" } }
```

A draft is only recovered if it is **more recent** than what is already saved, so it never hands you old text or duplicates anything.

## Pending changes

Changes that are not an entry yet live in `diario.pendiente-dia.v1`, as a patch per day:

```json
{
  "2026-10-04": {
    "patch": { "habits": { "h-3": true }, "counters": { "water": 6 }, "tomorrow": "Review the topic" },
    "savedAt": "…"
  }
}
```

The patch is merged with the saved entry to render the full day, and it is written to the notebook when you press «Save day». **An empty value is also a change**: deleting a text, setting a counter to zero or unticking a habit is saved just like anything else. In the JSON copy it travels as `pendingDays`.

## The lists you can change yourself

Two arrays live in `diario.setup.v1` and define what is rendered each day. `counters` are the Routine figures and `parts` are the entry's sections:

```json
{
  "counters": [
    { "key": "p-31", "label": "Push-ups", "unit": "reps", "min": 0, "max": 200, "step": 10, "goal": 50, "icon": "flame" }
  ],
  "parts": [
    { "key": "p-12", "label": "Head", "hint": "what you cannot stop thinking about", "type": "text" },
    { "key": "p-8",  "label": "Morning", "hint": "", "type": "line" }
  ]
}
```

- `type` is `text` (a paragraph on the today page) or `line` (a single line, like the word of the day).
- `key` is generated by the notebook itself (`p-<n>`), and it is the same one you will see in `entry.parts` and `entry.counters`. That is why **removing a part or a counter deletes nothing**: it simply stops being rendered, and what you already wrote and the figures you logged stay in every day in case you put it back.
- **Maximums: 8 parts and 12 counters.**
- There are eight starting labels (`COUNTERS` in `src/data/constants.js`) and eight writing presets (`PART_PRESETS`).

## The bottles

Thoughts travel in `diario.thoughts.v1`:

```json
{
  "id": "…",
  "text": "A loose thought",
  "castAt": "2026-10-04",
  "mood": 3,
  "sea": "breeze",
  "returns": true,
  "driftDays": 18,
  "arriveOn": "2026-10-22",
  "lostOn": null,
  "speed": 21,
  "current": "the cold current",
  "glass": "amber",
  "status": "drifting",
  "returnedAt": null,
  "reply": "",
  "weather": "wind",
  "wind": "westerly",
  "windSpeed": 19,
  "seen": false
}
```

| Field | What it means |
| --- | --- |
| `status` | `drifting`, `returned` (the spring tide brought it back) or `lost` (it sank), decided **when the notebook is opened** |
| `reply` / `kept` | Your reply and whether you anchored it |
| `weather`, `wind`, `windSpeed`, `push` | The signature of the day you cast it: it explains why it took as long as it did, and nothing more |
| `seen` | Whether you already read it when it came back |

**It never leaves the device.**

## Privacy

Everything happens on your device: **no servers, tracking, ads, remote fonts or artificial intelligence of any kind**. Your texts are never analysed by models; they are only shown exactly as you wrote them.

The sea is not magic either: bottles do not travel anywhere. Whether they return is decided by a **deterministic function** (`src/utils/ocean.js`) from the text, the date and the chosen sea, and the result is stored in your `localStorage`. Nobody else can read them, and your thoughts are not lost if you switch devices: **they travel inside your backup**.

### Your backup

From *Settings → Data*:

- **Export JSON** — the complete copy, including bottles and pending days.
- **Import JSON** — restore it in another browser or device.
- **Download copy** — the file to disk.
- **Delete everything** — with confirmation.
- **Half-finished days** — complete them or discard them.

> [!WARNING]
> Since everything lives in `localStorage`, clearing the site's data or browsing privately deletes the notebook. The only real protection is to **export a copy** from time to time.
