## Where each thing is edited

| What you want to change | Where |
| --- | --- |
| Home page sections | `content/home.fragment.html` |
| Project listing | `content/projects.fragment.html` |
| Contact block | `content/contact.fragment.html` |
| Error page and project detail | `content/404.fragment.html` |
| Blog posts | `content/blog/*.md` |
| Interface texts | `assets/js/i18n.js` |
| Styles | `assets/css/style.css` |
| Navigation and template | `scripts/layout.mjs` |
| Behaviour and data | `assets/js/main.js` |

> [!WARNING]
> **Do not edit `index.html`, `projects/index.html`, `blog/*/index.html`, `contact/index.html` or `404.html`.** They are generated on every build and overwritten.

## Adding a post

Create a Markdown file in `content/blog/` with a title and date in the front matter:

```md
---
title: "Post title"
date: "2026-10-04"
excerpt: "Short summary"
lang: "es"
---

Post text.
```

Then run the build. When you delete a source, **the build also removes the corresponding generated page**.

### Both translations are mandatory

The blog requires both languages for every post. Files are paired by slug:

```text
content/blog/lanzamiento-wave.md        # lang: "es"
content/blog/lanzamiento-wave.en.md     # lang: "en"
```

The build throws an explicit error in these cases:

| Error | When |
| --- | --- |
| `missing required "title" or "date"` | The title or the date is missing from the front matter |
| `Unsupported blog language: <lang>` | `lang` is neither `es` nor `en` |
| `Duplicate <lang> translation: <slug>` | Two files with the same slug and language |
| `Both es and en translations are required for <slug>` | One of the two versions is missing |
| `Translation dates differ: <slug>` | The dates of the two versions do not match |

The dates must match because the post is sorted once and shown with the same date in both languages.

### How the slug is generated

If you do not set `slug` in the front matter, it is derived from the filename: lowercased, non-alphanumeric characters converted to a hyphen and leading and trailing hyphens trimmed.

## How the language switch works

It is the site's most characteristic mechanism, and **this documentation uses it
as-is**. It has its own page: [The two languages](/website/i18n/) walks the
234-key dictionary, the five attributes that drive the substitution, detection
and persistence, the switch and the retyping animation.

The minimum to touch texts without leaving this page: the interface keys live in
`assets/js/i18n.js`, inside `dict.es` and `dict.en`, and the fields belonging to
each page in `pageTranslations`, generated by the build. Adding a key means
adding it **in both branches**, because the site checks that none is missing.

## Contacts and links

`content/contact.fragment.html` is reused on the home page and at `/contact/`. The email and the social links have **real links even without JavaScript**. The copy button only appears with JavaScript and **reports if the copy fails**.

The by-topic shortcuts prepare an email subject; **they do not send messages or store data**.
