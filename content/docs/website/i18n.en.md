# The two languages

The whole website exists in Spanish and in English, and they are not two sites
nor two routes: it is a single HTML document that rewrites itself in the browser.
This page walks the mechanism end to end —the dictionary, the attributes,
detection, the switch and the retyping animation— and ends with what this
documentation inherits from it.

## One HTML, two languages

The HTML is always served in Spanish. The English texts do not live in another
folder or under an `/en/` prefix: they travel inside the same page and are applied
when somebody presses the switch.

Two places carry them:

1. **`assets/js/i18n.js`** — 38,251 bytes and 674 lines holding the `dict`
   dictionary for the whole interface.
2. **`<script type="application/json" id="pageTranslations">`** — the fields
   belonging to each page, generated by the build: title, description, body and
   date.

The practical consequence is that there is **one URL per page**, one `canonical`
and one `sitemap.xml`. The language is a browser state and not an address, so
there is no duplicated content to maintain and no links crossing between
versions.

> [!NOTE]
> The price is that a crawler that does not run JavaScript sees the Spanish
> version. It is offset by rewriting the metadata on language change and by not
> declaring `hreflang` at all: there are not two documents to relate.

## The dictionary: 234 keys

`dict` has two branches, `es` and `en`, with **exactly the same 234 keys**. They
are grouped by prefix, and the ten most populated ones say where the weight of
the site is:

| Prefix | Keys | What they are |
| --- | --- | --- |
| `github.*` | 52 | Contribution calendar, synchronisation and its errors |
| `contact.*` | 27 | Email access, copy to clipboard and social networks |
| `status.*` | 25 | The status page and the incident.io panel |
| `meta.*` | 16 | Title and description of each page, by route |
| `project.*` | 14 | Project card: stars, forks, demo and load failures |
| `footer.*` | 12 | Footer, link columns and legal notice |
| `hero.*` | 11 | Home page: headline, calls to action and activity line |
| `about.*` | 10 | The about section and its card |
| `discord.*` | 10 | Discord presence and its states |
| `aria.*` | 8 | Accessible labels with no visible text |

The eleven remaining prefixes —`skills`, `nav`, `projects`, `social`, `blog`,
`legal`, `profile`, `notFound`, `projectsPage`, `projectsTeaser` and `readme`—
add up to the other 49 keys.

### The module's functions

Eight declared functions plus the animation loop, which lives inside one of them:

- `applyLang(lang, { persist, animate })` — applies a language to the whole page
  and tells the rest of the site.
- `detectDefaultLang()` — decides which language the page opens in.
- `storageGet(key)` and `storageSet(key, value)` — `localStorage` wrapped in
  `try/catch`, because private mode throws.
- `retypePage()` — the retyping animation.
- `collectTypingBlocks()` — which blocks get typed and which do not.
- `stopRetyping()` — cancels a running animation and cleans up after it.
- `motionAllowed()` — queries `prefers-reduced-motion`.
- `frame(timestamp)` — the `requestAnimationFrame` callback, declared inside
  `retypePage`.

Everything is published on `window.i18n` so that `main.js` can request a language
change or retype the page after painting new content.

## The attributes that drive the substitution

Five attributes plus one more query. The first four look at the dictionary; the
fifth looks at the page's own JSON block:

| Attribute | What it replaces | Detail |
| --- | --- | --- |
| `data-i18n="key"` | the `innerHTML` | Values may carry markup: `<span>`, `<strong>`, `<br>` |
| `data-i18n-aria="key"` | the `aria-label` | For icons and buttons with no visible text |
| `data-i18n-title="key"` | the `title` | The tooltip follows the chosen language |
| `data-i18n-date` | the text of a `<time>` | The `datetime` stays ISO and is never touched |
| `data-content-key="field"` | from `pageTranslations` | The page body, not the dictionary |

### data-content-key and data-content-language

The interface fits in a dictionary; the body of a post or the text of a legal
page does not. Those fields go in `pageTranslations` and are applied through
`data-content-key`. When the element also carries `data-content-language`, the
content is treated as HTML and the element's `lang` attribute is adjusted, so a
screen reader pronounces English as English even though the document declares
`lang="es"`.

### data-i18n-date

Dates are not translated: they are formatted. `data-i18n-date` on a
`<time datetime="2026-03-14">` goes through `Intl.DateTimeFormat` with the
`es-ES` or `en-US` locale according to the active language, and the `datetime`
—the one read by search engines and stylesheets— never changes.

## Detection, persistence and several tabs

```js
function detectDefaultLang() {
  const saved = storageGet("lang");
  if (saved && dict[saved]) return saved;
  const browserLang = (navigator.language || "es").slice(0, 2).toLowerCase();
  return dict[browserLang] ? browserLang : "en";
}
```

The order is saved preference, browser language, and English as the fallback. The
preference is stored in `localStorage` under the `lang` key, and a listener for
the `storage` event makes **several open tabs change at once**: choosing English
in one rewrites the others without reloading them.

That key is the same one this documentation uses, and it is not a coincidence:
the language chosen on the website is kept when entering `/Docs/` and the other
way round.

## The switch

### The flag and its gesture

The `#langSwitch` button carries a Spanish flag and a British one drawn as SVG
patterns, with their gradient, their three circles and two `<use>` elements, and
shows one or the other according to `data-active`. Its `aria-label` comes from
`aria.langSwitch` and announces the **destination**, not the state: "Switch to
English" while in Spanish. Next to it, `#languageName` says "Español" or
"English" as text.

Pressing it adds the `is-switching` class for 760 ms, which triggers
`@keyframes globe-spin` —the globe turns once— and `globe-ring` —its ring expands
and fades—. The class is removed, the reflow is forced by reading `offsetWidth`
and it is added again: without that step, two presses in a row would not replay
the animation.

### The retyping

Changing language does not swap the texts bluntly: it erases them and types them
again. It is the site's most characteristic animation and it has its own numbers:

- Each block starts **15 ms** after the previous one, capped at **380 ms** so a
  page with a hundred texts does not take long to begin.
- Speed goes from **3 to 13 ms per character**, computed as `900 / total` and
  clamped, so a short text reads like typing and a long one does not drag.
- Only blocks of between **2 and 320 characters** are typed: under 2 is not
  noticeable and over 320 would take seconds.
- Before emptying a block its height is measured and reserved with `min-height`;
  otherwise the whole page shrinks and grows again while typing and the reader
  loses their place.
- While it lasts, the block carries `aria-busy="true"`, which is what a screen
  reader needs to avoid reading it half way.

> [!IMPORTANT]
> Three guards disable it: the first language application is never animated,
> `prefers-reduced-motion: reduce` turns it off entirely, and a background tab
> does not type. Also excluded are `#typedRole`, which already has its own
> typing, `[data-content-language]`, `[aria-live]` —retyping a live region shouts
> every character at whoever is listening—, `.jg-loader`, `pre`, `code` and
> `textarea`.

## Translating content, not just interface

### The blog

Each post is two files, `content/blog/<slug>.md` and `<slug>.en.md`, and the
build forgives neither a missing one nor two that have drifted apart:

```js
if (!["es", "en"].includes(post.lang)) throw new Error(`Unsupported blog language: ${post.lang}`);
if (translations.es.date !== translations.en.date) throw new Error(`Translation dates differ: ${slug}`);
```

The second check is the interesting one: two translations with different dates
would produce two entries in the blog list for the same post, and it is a mistake
nobody would spot by looking at the page.

### The legal pages

The legal texts are complete HTML versioned in both languages: `terms.es.html`
(13,216 bytes) with `terms.en.html` (12,288), and `privacy.es.html` (11,479) with
`privacy.en.html` (10,760). They are narrated in full in each language instead of
being translated sentence by sentence, and they apply to every project without
naming any.

## Metadata and search engines

A language change also rewrites what cannot be seen:

| What | Where it comes from |
| --- | --- |
| `document.title` | `meta.<route>.title` |
| `description`, `og:description`, `twitter:description` | `meta.<route>.description` |
| `og:title` and `twitter:title` | the same title |
| `og:locale` | `es_ES` or `en_US` |
| JSON-LD `person.description` and `person.inLanguage` | the `#personStructuredData` block |

Rewriting the structured data is what makes a rich result match what the page
shows after changing language.

## What this documentation inherits

The model was copied whole, with two adaptations that come from being a
documentation site rather than a portfolio:

| Piece | On the website | In this documentation |
| --- | --- | --- |
| Dictionary | Inside `i18n.js`, 234 keys | One `#uiStrings` block per page, with keys derived from the registry |
| Page body | `pageTranslations` | The same, plus sidebar index, reading time and edit link |
| Attributes | `data-i18n-title` | `data-i18n-placeholder`, for the search field |
| Stored key | `localStorage["lang"]` | The same one, shared between the two sites |
| Retyping | Yes | Yes, ported with its numbers |
| Switch | Globe with two flags | The same globe and the same 760 ms |

That last column deserves a nuance. The block does not carry only the
hand-written texts: `scripts/dict.mjs` joins the 157 keys of `content/ui.mjs`
with those derived from the registry —the name, tagline, summary and status of
each project, the title of each guide and the title and description of each
group—, and the block adds up to 237 keys. This way the sidebar index, the cards
and the filters are written once in HTML and translated in the browser like any
other text.

The third row is the only real difference in the contract: here no element needs
a translated `title` —the six that exist are project proper names— and instead
the search field needs its `placeholder` translated.

## The tests that watch it

Eight of the 35 tests in `tests/site.test.mjs` deal only with languages:

- That the globe alternates the flag state with an accessible destination label
  and persists the choice.
- That every generated label and metadata has a translation in both languages.
- That the profile and the public repositories really are painted **and survive a
  language change**.
- That the blog translates the complete article, the dates, the image
  descriptions and the SEO without duplicating posts.
- That the legal texts are narrated in full and mirrored in both languages.
- That a README's accessible labels follow the chosen language **without
  modifying the original document**.
- That changing language retypes the page and honours `prefers-reduced-motion`.
- That a page's localized payload **cannot close its own JSON `<script>`
  element**, which is the way a translated text would break the page.

> [!TIP]
> The last one is worth remembering when adding keys: every dictionary value ends
> up serialized inside a `<script type="application/json">`, so a `</script>`
> sequence in a text —even one coming from a README— would close the block early.

This documentation applies the same pattern and checks it the same way: its tests
load a generated page in `jsdom` with its own scripts and press the switch for
real. The complete tour of the site is in
[Overview](/website/).
